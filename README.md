# Правила командної розробки та інтеграція з Jira

Ключ задачі (наприклад, KAN-123) обов'язково має бути присутній у назвах гілок, комітів та PR для автоматичної прив'язки до Jira.

---

### 1. Назви гілок (Branch Naming)
Усі нові гілки створюються виключно від гілки develop:
- feature/KAN-<номер>-<короткий_опис> — для нової функціональності
- fix/KAN-<номер>-<короткий_опис> — для виправлення багів
- refactor/KAN-<номер>-<короткий_опис> — для оптимізації / структуризації коду

Приклади:
- feature/KAN-12-registration-form
- fix/KAN-45-json-deserialization-error

---

### 2. Повідомлення комітів (Commit Messages)
Ключ задачі вказується на початку повідомлення:
- KAN-<номер>: <що зроблено>

Приклади:
- KAN-12: add validation for user email input
- KAN-45: fix null reference when loading empty json

---

### 3. Pull Requests (PR)
- Base branch (куди мерджимо): develop.
- Назва PR: KAN-<номер>: <Зрозумілий опис змін>
  (Приклад: KAN-12: Реалізовано форму реєстрації та валідацію вхідних даних)
- Опис PR:
```markdown
### Що зроблено:
- Додано інтерфейс для нової форми
- Налаштовано серіалізацію списку в JSON

### Задача в Jira:
- KAN-12
